## Design Specificity Verdict

**LLM assessment:** High specificity, not generic AI slop. Orbit has a coherent bespoke identity ("Quiet Slate"): near-black plum ground, rose-tinted paper light theme, a single muted rose accent reserved for the live edge, Pretendard Variable typography, a dense but consistent token system, and a documented design contract (DESIGN.md ↔ styles.css). Minor drift risks: one off-token button radius (10px on "New workspace"), section labels colored in the accent, a few lucide-icon defaults. No purple gradients, glassmorphism cards, or Inter.

## Overall Impression

Orbit is a mature, opinionated, product-specific interface with an excellent foundation (38/40). The main opportunities are (1) reclaiming the rose accent's semantic exclusivity, (2) reducing composer density on phones, and (3) adding first-run onboarding for pairing/push. Detector micro-issues are largely inherent to the compact-density design.

## What's Working
1. **Token-driven, documented design system** with density variants and theme generation — rare consistency.
2. **Calm resting state discipline** — destructive actions neutral, danger only at risk, single rose accent.
3. **Accessibility fundamentals** — 44px touch targets, live regions, reduced-motion respect, keyboard operability.

## Priority Issues
1. **[P1] Accent-text contrast below WCAG AA** — Sidebar "Agents" section label uses `--accent-text` (#d9558f) at 12px/500; measured 4.44 vs 4.5. Fix: bump to ~#e06a9f or switch section labels to `--text-dim`, reserving rose for chosen row/focus. Suggested: `/harden`.
2. **[P1] Sidebar section labels in rose dilute accent semantics** — `.sidebar-section-label { color: var(--accent-text) }` makes "Agents" read as interactive/active. Fix: neutralize section labels (`--text-dim`), keep rose for chosen row + focus only. Suggested: `/colorize` (or `/quieter`).
3. **[P2] Composer cognitive load on mobile** — Five always-visible quick replies + model info + folder strip + voice/attach on 390px. Fix: collapse quick replies into a single "Suggest" chip on narrow viewports; reveal on tap. Suggested: `/distill`.
4. **[P2] Off-token button radius** — "New workspace" uses 10px radius (not in `--radius-*`) and weight 700. Fix: use `--radius-md` (8px) and `--fw-semibold` (600). Suggested: `/normalize`.
5. **[P2] Missing first-run onboarding** — No guidance for device pairing, push permission, or terminal toggle on first load. Fix: lightweight first-run sheet shown once. Suggested: `/onboard`.
6. **[P3] Cramped padding / tight leading (detector)** — `agent-item` flush top/bottom, `toggle-button-group` flush, 1.20x leading. Fix: verify intended compact density; bump leading to ≥1.3 where text wraps. Suggested: `/audit`.

## Persona Red Flags
- **Alex (power user):** Sidebar reordering drag handles and dense status dots; workspace list with 5+ items may feel cramped; "More" menus multiply. Risk of losing track of which pane is live.
- **Sam (mobile companion):** Composer density (quick replies + model info) competes with thumb reach; horizontal-scroll quick replies hide overflow; 24px glyph buttons depend on invisible expanders — needs real-device pass.
- **Casey (casual/new user):** No onboarding; "DONE" status is sr-only so state isn't obvious; agent session titles with pipes ("OC | …") are cryptic as pane labels.

## Cognitive Load
- **Medium-high, managed.** Composer simultaneously exposes quick replies, model name, reasoning level, folder strip, voice, attach, send. Quiet mode collapses model text at rest (good mitigation), but first-time users still face lots of chrome.
- Sidebar mixes host, workspaces, agents, install, settings in one column with subtle section labels — scannable but dense at 3+ workspaces.
- Status info sometimes sr-only (e.g. "DONE"), so sighted users infer state from color/dot; acceptable for power users, risky for casual ones.
- Quick replies scroll horizontally (no wrap) — efficient but overflow discoverability depends on scrollbar hiding.

## Emotional Journey
- **Calm and focused at rest** — neutral destructive controls, danger only at risk, muted status colors. Matches "couch glance" ritual well.
- **Trustworthy** — local-first, no telemetry, draft safety reduces anxiety about lost input.
- **Friction points:** (a) composer density can feel like "cockpit" on first use; (b) empty/onboarding gap means new users may not discover push/pairing; (c) agent "finished" state is quiet to the point of being easy to miss.

## Questions to Consider
1. If rose is "the live edge alone," why do section headers wear it? What if the sidebar were entirely neutral except the chosen row?
2. The composer is the most-engineered component in the repo — is that complexity earning its keep for a phone user approving a "yes"?
3. Status "DONE" is hidden from sighted users by design; what happens when a user glances from across the room?
4. Quick replies are always the same five regardless of agent state — should they be contextual or hidden when blocked
